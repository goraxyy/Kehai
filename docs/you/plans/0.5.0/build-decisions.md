## Shelf proposal, explained more simply

Think of the shelf as **a shared lower unit plus an optional top section**:

| Height above floor | Low shelf | Tall shelf |
|---|---|---|
| 0.225 m | bottom board | same bottom board |
| 0.7375 m | second board | same second board (currently about 8 cm higher; proposed change) |
| 1.25 m | backing stops with a finished cap | backing continues upward |
| 1.4083 m | no board | third board |
| 2 m | — | tall backing stops |

At a low/tall join, the bottom two boards line up. The tall side's upper section ends with a
finished vertical panel; nothing sticks out unsupported above the low side. At a corner/T, only
arms that connect to tall shelves get the upper section. It should look like matching furniture
of two heights, not a tall pillar jammed into a low shelf.

These are proposed geometry dimensions, not a remodel already done. The [evidence page](shelf-remodel.md)
records the source measurements, offsets and stock-clearance checks. If a joint cannot be made
cleanly, use two finished end caps with an intentional gap rather than overlap meshes.
The engineering task owns a small prototype and a contact sheet before widespread replacement.
It needs no new owner questionnaire; later picture review is an ordinary art milestone.

## Remaining execution gates, not open design questions

- **Explicit instruction to build.** The owner currently says documentation only. No Unity,
  modelling, project creation, imports, baking, training or game code now.
- **Suitable storage before active external visual work.** Recommend a 500 GB/1 TB USB 10 Gb/s
  SSD. If only the linked stick is bought, archive/transfer there and keep active visual work on
  Windows SSD; do not silently create an unusably slow Mac project.
- **Actual private-page integration capability.** The selected product is a private summary
  page, previously described as a claude.ai page. Automatic external writes/authentication must
  be verified before implementation claims. Treat inability as an integration blocker, not
  permission to invent an API, expose data publicly or require a board.
- **Measured hardware/graphics budgets.** First build measures memory, frame time, Windows
  parallelism and scene-cache growth before promising minimum specs or download sizes.
- **Long-run go after 0.5.0.** Set benchmark definitions and held-out splits before testing;
  preserve cautious-player isolation and report negative results.

No purchase, formatting, deletion, file movement, upload or deployment is authorised merely by
recording these choices. No requirement to buy a particular brand. Model/art assets and project
settings remain private; public implementation contains code and documentation only.
