## 6. Item 1: testing and training with less friction

**The full page, with today's measurements:** [testing and training](0.5.2/testing.md).

**Today, checked in the code and on the disk** (the evidence is on the page, [§1](0.5.2/testing.md#1-what-gets-in-the-way-today)):
- **Seven copies of the lock code**; four of them never take over a dead holder's lock, and the
  trick-video script doesn't free it when stopped. That's the stale lock you hit.
- **Clean-up runs only on a normal exit,** so a crash leaves the clone, the prefs and the lock.
  The prefs are put back to `~/Developer/Kehai` whatever they said before.
- **Each test clones the whole main folder,** worktrees included, then deletes them, and never
  removes files the branch deleted, so it can compile stale code.
- **Unity's start costs far more than small tests,** and compiles the scripts twice (0.5.1's run
  of 15 November).
- **Ablations can't resume;** training resumes only by hand; nothing says when a run ends.
- **The "3.6 times" is old:** two fixes shrank it, and the gap against 0.2.0 hasn't been
  measured since 8 November.
- **Two full copies of your private files exist,** nearly the same; which is the source is Q20.
