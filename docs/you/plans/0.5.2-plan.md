## 6. Item 1: testing and training with less friction

**The full page, with today's measurements:** [testing and training](0.5.2/testing.md).

**Today, checked in the code and on the disk** (the evidence is on the page, [§1](0.5.2/testing.md#1-what-gets-in-the-way-today)):
- **Seven copies of the lock code**; four of them never take over a dead holder's lock, and the
  trick-video script doesn't free it when stopped. That's the stale lock you hit.
- **Clean-up runs only on a normal exit,** so a crash leaves the clone, the prefs and the lock.
  The prefs are put back to `~/Developer/Kehai` whatever they said before.
- **Each test clones the whole main folder,** worktrees included, then deletes them, and never
  removes files the branch deleted, so it can compile stale code.
- **Unity's start costs far more than small tests,** and compiles the scripts twice (0.5.1's run
  of 15 November).
- **Ablations can't resume;** training resumes only by hand; nothing says when a run ends.
- **The "3.6 times" is old:** two fixes shrank it, and the gap against 0.2.0 hasn't been
  measured since 8 November.
- **Two full copies of your private files exist,** nearly the same; which is the source is Q20.

| Part | My pick | Other options considered | Page |
|---|---|---|---|
| One safe command | **`kehai-run`**, one Python tool for every job, with a run card for clean-up after a crash | a shared shell file; a checklist | [§2](0.5.2/testing.md#2-one-command-that-runs-a-test-safely) |
| A warm clone | **stop the double compile first;** keep a warm clone on the Mac if you allow the disk, else on the PC | a fresh clone each run | [§3](0.5.2/testing.md#3-a-warm-clone) |

| Resume | **ablations resume by career;** training restarts itself; recordings resume by stage; the run-to-run jitter found, then fixed | resume by shift; one career per job | [§7](0.5.2/testing.md#7-runs-that-survive-interruption) |

### Phase 1: one safe run command [C] · Sonnet 5.5 · this Mac, no Unity

- [ ] **C1.1 One lock for every job** (`tools/run/lock.py`): the holder's process id and start
  time; a dead holder's lock is taken over and logged; it says who holds it, waits if asked, and
  exits 75 when busy. The marketing tools read the same files.
  - Done when: a test kills a holder with `kill -9` and the next job takes the lock; no bare

    terminal closed, a timeout) and leaves nothing behind in any of them.
- [ ] **C1.3 Clean-up after a crash, and `kehai-run doctor`:** every start cleans dead runs from
  their cards; `doctor` lists leftovers, cleans what `kehai-run` made, and asks before touching
  anything else (today's old verify folders: Q5).
  - Done when: after `kill -9` mid-run, the next run removes the clone, the prefs file and the

## 12. Honest limits

- **Nothing was run in Unity for this plan.** The timings are single tries on a busy Mac; the
  rest are estimates, marked.
- **The warm clone's start time and disk cost are guesses** until C6.1 measures them.
- **The Unity-free lane's share is an upper bound** from counting test files; some of those
  tests will still need the engine.
- **The slowdown may be gone,** or may live in the editor itself, where only a built player avoids it.
- **Exact repeats aren't possible today:** later shifts drift a little in every run, so resumed
  runs are checked against the spread of normal runs, not row for row.
- **The PC's readiness is unknown** (Q19): its project predates 0.5.0.
- **Visible hiding is described from work not yet committed,** which can change before 0.5.1 merges (C0.1).
- **Two repos in one folder is a new risk.** The guards (C7.2) are tested before the first upload.
- **Unchecked:** whether LFS locks work on files not stored in LFS; GitHub's time limit for jobs
  on a self-hosted runner; whether Unity's profiler flags capture in batch mode.

## 14. Terms

| Term | What it is | How Kehai uses it | Real-world example |
|---|---|---|---|
| APFS clone | a copy of files that shares their space on disk until one side changes | the test copy of the project, made in under a minute | duplicating a big video in the Mac's Finder takes a second and no space |
| Warm clone | a test copy kept between runs, so its cache stays ready | `kehai-run --warm` (C6.1) | leaving the oven on between two batches of bread |
| Heavy-work lock | a marker saying "a heavy job is running"; others wait | `heavy.lock`, so only one Unity, render or training runs at once | the "occupied" sign on a toilet door |
| Stale lock | a lock left by a job that died | the cause of last week's blocked jobs; C1.1 takes it over | an "occupied" sign left on after the person has gone |
| Run card | a note a job writes before it starts, saying what it will create and change | how `kehai-run` cleans up after a crash (C1.3) | a hotel's check-in card, so housekeeping knows the room to clean |
| Process id | the number the computer gives each running program | the lock stores it, with the start time, to tell a live holder from a dead one | a ticket number at the deli counter |
| Batch mode | Unity run with no window, from a command | every test, ablation and editor training run | a dishwasher's quick cycle: nobody watches it |
| Script compile | turning C# into what Unity runs | 20 s of every Unity start; twice by mistake today (C6.2) | an app updating itself before it opens |
| Profiler | a tool that measures where a program spends its time | to find the batch slowdown (C6.4) | a phone's battery page, showing which app used the most |
| Development player | a built game with extra checks and measuring left in | one of the three speeds measured in C6.3 | an app's beta version |
| Checkpoint | a saved state a long job can restart from | training saves one every 50,000 steps | a save point in a video game |
| Resume | carrying on from where a stopped job left off | ablations by career (C5.1), training by checkpoint (C5.2) | a download that continues after the Wi-Fi drops |
| Private network | a link between your own devices over the internet that nobody else can join | Tailscale between the Mac and the PC (Phase 3) | AirDrop, but across the internet |
| SSH | a secure way to type commands on another computer | the Mac starts and watches jobs on the PC | remote-controlling a computer, in text |
| Self-hosted runner | a program on your own computer that runs jobs GitHub sends | option C for the PC, only on the private repo | a printer at home that prints what you send from your phone |
| Git LFS | an add-on that keeps big files out of git's normal history, storing them on the server | models, textures and audio in `kehai-assets` (option B) | a photo app keeping full-size pictures in the cloud and small previews on the phone |
| File lock | a mark that says "I'm editing this; wait" | on scenes and prefabs while someone edits them | "checked out" on a library book |
| Merge tool | a program that combines two people's edits of one file | `UnityYAMLMerge` for scenes and prefabs | Google Docs combining two people's typing |
| Force Text | Unity's setting to save scenes as readable text | on, so scenes can be compared and merged | saving a document as plain text, not as a picture of a page |
| Generated scene | a scene file made by code from another, never edited by hand | `Store_Training.unity` (C8.1) | a PDF exported from a Word file |
| Additive scene | a scene loaded on top of another, both at once | a dev scene on top of the store (C8.4) | a tracing-paper sheet laid over a map |
| Prefab | a saved, reusable group of game objects | the shelves, doors and props; per-room prefabs later (option F) | a furniture set you can drop into any room in a home-design app |
| Unity Version Control | Unity's own system for sharing projects and their history | option D | Google Drive's version history, built into one app |
| Perforce (P4) | the version control big game studios use for huge art | option E | a company's central file server with sign-out sheets |
| Download allowance | how much may be downloaded free each month | LFS's free monthly downloads on GitHub, which is why data goes by direct copy | a phone plan's monthly data |
| Sparse checkout | git fetching only some folders of a repo onto a computer | option B1: each computer takes only its part of `kehai-assets` | a music app downloading only the playlists you picked |
| Run-to-run jitter | small differences between two runs that should be the same | one seed gives slightly different shifts; C5.4 finds why | two loaves from one recipe never come out identical |
| Witnessed entry | her memory of seeing you go into a hiding place | visible hiding (0.5.1) and I2, I3 | a bystander telling the police "he went in there" |
| Source scan | a test that reads the code and fails if her brain reads your true position | every interaction keeps it passing | a spell-checker for cheating |
| Usage limit | how much an account may use Claude in a time window | why sessions stopped mid-task; Phase 2's rules | a phone's screen-time limit |
| Subagent | a helper a Claude session starts for one piece of work | at most one Opus subagent at a time | a chef handing one dish to a sous-chef |
