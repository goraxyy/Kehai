## APIs and lifecycle

The namespace is **global**, not `Kehai.Edition`.

- `KehaiEdition { Training, Testing, Gameplay }`; `Edition.Current`, `.Training`, `.Testing`,
  `.Gameplay`, `.ShowUI`, `.AllowGuide`, `.AllowDebugTools`, `.AllowEvaluation`, `.RecordReplays`,
  `.RecordShiftData`, `.ShouldKarenAppear(int shift)`.
- Editor defaults to Testing, with editor-only `Edition.EditorOverride`. Player editions use
  compile-time stamps; an unstamped player defaults to Gameplay. No runtime edition override.
- `CareerRuntime.GameplaySimulation` resets false at subsystem registration. Parent sets it
  before validated, non-learning benchmark reloads in Training/Testing. Gameplay or simulation
  means no Karen on shift 1; otherwise Training/Testing have her from shift 1. Gameplay evaluation
  must be rejected before side effects (`Edition.AllowEvaluation` is false there).
- `CareerRuntime.CareerPreparing(int shift, int seed, bool training)` is the static layout hook.
  Parent subscribes and calls StoreLayoutRuntime; this slice makes no direct layout calls.
- `ShiftManager.PrepareUpcomingShift()` raises preparation while inactive, before task setup and
  before Karen's `ShiftStateChanged` handler. It runs at Start, explicit placement and clock-in;
  subscribers must be idempotent. Initial layout setup reads `CareerRuntime.UpcomingShiftNumber`
  and `.Seed` before stock/map setup.
- `CareerRuntime.PendingCompletedShifts` is set before a reload; ShiftRestart does this, then
  clears it after restoration. Eval pending placement remains the parent's responsibility.
- `ShiftManager.CompletedShifts`, `.ShiftNumber` (attempt), `.UpcomingShiftNumber`, `.CareerSeed`,
  `.CareerComplete`, `.LastShiftCompleted` and `.CareerCompleted` are public.
- `EndShift(bool completed = true)`; deaths/aborts pass false. Four successful shifts finish;
  failed night four remains retryable. Consequences.Death passes false. The completion screen
  returns to the menu, and Continue cannot start night five.
- Successful progress, seed and optional guide skip are saved atomically in `career.json`,
  independently from Ledger attempt statistics. Legacy migration uses
  `min(shiftsWorked, shiftsClockedOut)`. Training, batch and eval overrides do not read/save
  human progress. Any Ledger wipe also calls `CareerRuntime.NewCareer()`; menu and playtest
  tester changes do this.
- ShiftManager sets `SaleRules.NormalCap` at setup, calls `PhaseOneFixtures.ResetForShift()`,
  and ends the sale at door close/end. Parent owns matching Env reset hooks. Old diagnostic
  callers must remain within shifts 1–4; the TrickCheck caller now uses shift 4.

## Guide and build surface

`FirstShiftGuide` installs on the scene's ShiftManager. Public: `.State` (pure
`FirstShiftGuideState`), `.Available`, `.Skip()`, static `.WantsTaskList`.
`GameEvents.TaskListOpened`/`.RaiseTaskListOpened()` is the additional action hook. Other lessons
consume existing action/world events. One active thought, four seconds of text, one reminder
at 30 seconds, slow shared outline blinking (hover stays steady), no E prompt on automatic doors, an optional Settings
skip, and no Help replay. Jobs can arrive in either order; closing and early clock-out cannot
leave an optional lesson blocking the guide. Training, bots, batch, replay and later shifts
are excluded.

KehaiBuild accepts `-edition training|testing|gameplay -platform windows|macos`; KehaiRl requests
Training explicitly. Scene-copy preprocessing strips presentation/debug components and
serialized art/audio references for Training, retaining collision, navigation and perception
lights. Gameplay development builds and conflicting edition defines are rejected. Stamps are
written before macOS signing. Parent owns final build provenance additions.
