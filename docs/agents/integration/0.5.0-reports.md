# 0.5.0 reporting / benchmark / status integration (Python slice complete)

Direct shared-worktree changes; no commits, Unity, training, or deployment. This build instruction
supersedes the old documentation hold. Owner: new `tools/reports/`, `tools/benchmark/`,
`tools/status/` and their tests/docs. Other workers' C#, RL/belief and existing learning commands
are not edited here.

Parent hooks (Python stdlib, invoke from repository root):

- Run register: `python3 -m tools.reports.register --register <PRIVATE>/runs.jsonl run --kind
  record|fit|train|tune|test|benchmark --manifest <data.json> --input <config> --card <result-card>
  -- <literal command and args>`. Start/terminal events include id, computer, commit/dirty,
  explicit file hashes/data snapshot, seeds, timestamps, exit status, result card. No shell.
  Training/fit/record/tune use the manifest split gate. Test/legacy imports may report missing
  metadata without inventing it. Existing commands can be wrapped without editing their source.
- Python API: `tools.reports.register.append(path, event)`, `latest(path)`, `audit(manifest,
  purpose)`; `tools.benchmark.suite.allowed(career, 'train'|'tune'|'evaluate')`,
  `schedule(purpose='evaluate', half='practice'|'hidden')`. Integration should call the gate
  before any job that can fit/tune Karen. No claim that an arbitrary unwrapped command is gated.
- Benchmark runner: `python3 -m tools.benchmark.cli run --home <PRIVATE> --model <immutable
  release-id> --arm planner -- <adapter>`. Adapter receives **request.json rows.jsonl** as its
  final two arguments. It runs the request's complete careers and retained/wiped conditions,
  preserves request seeds/personas/layouts/edition, and emits one row per shift/condition.
  Frozen IDs will match `StoreLayouts`: `today`, `racetrack`, `labyrinth`, `fishbone`,
  `brick-bond`, `rings`, `split`. Shift 1 has no Karen in this Gameplay benchmark; habits still
  recorded. Testing edition is a separate future benchmark definition (no pooling editions).
- Required row fields: `model`, `arm`, `definition_sha256`, `seed`, `player`, `shift`, `layout`,
  `edition: gameplay`, `ledger: retained|wiped`, `metrics: {key: finite number|null}`.
  Missing metrics stay null; do not infer fairness/stuck/catch from an absent field.
  Optional `survival: {seconds: <followup>, caught: <bool>}`, `pacing: false` supports Vital KM.
  Unknown/duplicate identities or mismatched definition hashes fail. CLI help and README give
  the final metric keys and fixtures. Hidden evaluation is reserved once per release+arm before
  execution, even when a job fails; no tuning access to hidden/cautious/careful/Rings/Split.
- Reports: `python3 -m tools.reports.report --card <existing historical JSON/md> --out
  <PRIVATE>/run.html`; `--run ID --manifest ... --score ... --comparison ... --curves ...` optional.
  Replay: `python3 -m tools.reports.replay_cli <ShiftRecording.json> [second.json] --out ...`.
  Two-record pairing needs explicit same seed/shift/layout. No layout metadata is guessed for
  old recordings. Recorded `plan` geometry is supported; absent neural data says unavailable.
- Optional decision trace JSON: `{seed, shift, model_sha256, decisions:[{t, inputs:[...], branch,
  choice, probabilities:[...]}]}`. `--decisions trace.json --model brain.part.json` must hash-match
  exactly. Feed-forward Swish exports can show recomputed activations and an analytic local
  derivative of the **chosen head logit** (not a causal explanation/probability attribution).
  LSTM/recurrent models are explicitly unsupported for attribution until full state is recorded.
- Status: `python3 -m tools.status.cli collect --repo . --home <PRIVATE> [--score score.json]
  [--tests results.xml] [--build build.txt] [--github OWNER/REPO] [--marketing-dir DIR]`.
  Produces latest.json, observed 30-day history.jsonl, status.html outside every git checkout.
  No credentials required; GitHub uses an existing `gh` session only on opt-in. APIs without
  accounts stay unavailable. `render` makes static private HTML. `serve` binds authenticated
  loopback only; no automatic external page writes or remote hosting.

## Parent transport hook (original request; now implemented as source)

At the original inspection the server exposed reset/step/observe/map/metrics/close only. Setting
`EnvConfig.agent` labels an external driver; it does **not** instantiate the efficient/cautious
or trained player. Reusing run_baseline.choose and relabelling it would invalidate the suite.
I am adding a bundled `tools.benchmark.env_adapter`, now the default runner, using the existing
KehaiEnv TCP client. Parent owns the C# integration; please implement these exact nonlearning
commands in EnvServer (or tell this task a concrete existing equivalent):

1. `{"cmd":"benchmark_capabilities"}` -> `ok:true`, `benchmark_protocol:1`,
   `build_edition:"training"|"testing"`, `career_semantics:"gameplay"`, `build_commit:<actual compiled commit>`, `arms:[...actually present...]`,
   `players:[efficient,skittish,reckless,cautious,trained-range,careful-corner]`,
   `layouts:[today,racetrack,labyrinth,fishbone,brick-bond,rings,split]`,
   `four_shift_careers:true`, `model_sha256:<actual selected part hash if applicable>`.
   Unsupported/missing generated minds must stay absent/unavailable, never heuristic fallbacks
   under trained labels. Adapter preflight refuses unsupported arms/players/layouts.
2. `{"cmd":"benchmark_career","benchmark_protocol":1,"definition_sha256":...,
   "model":...,"arm":...,"half":...,"purpose":"evaluate","career":<one exact scheduled career>,
   "ledger":"retained"|"wiped","horizon_seconds":150}` -> `ok:true`, `rows:[...]`.
   Play exactly this 4-shift career with its actual SimulatedPlayer/Employee mind and 14 traits;
   retain bot memory across shifts; set the requested layout at each shift, no Karen at shift 1
   but habit recording active; reset Karen's Ledger at career start, additionally before each
   shift in wiped. Vital pacing off. Mark absent trained models unavailable rather than substitute.
   Each response row: `executed:{seed,player,shift,layout,edition,ledger,arm,traits,karen_present}`
   reflecting actual runtime state, plus `metrics:<EpisodeMetrics.ToDictionary()>`.
   Optional `recording:<actual ShiftRecording JSON>`, `decision_trace:<actual trace JSON>`.
   Optional `metric_samples:{panic_setpoint_rmse:N}`, `pacing:false` for verified Vital survival.
   Adapter archives raw replies and normalizes only fields actually present. No probabilities,
   gradients, calibration, timings or trajectories are invented from summary metrics.

Parent has since implemented `BenchmarkCareer.cs`, both EnvServer commands and gameplayCareer.
Until that hook is in a compatible compiled build, bundled adapter exits with an explicit capability error;
the fake TCP test proves Python protocol plumbing, not a played game. No heavy run is needed

## Edition correction and exact EnvConfig needs

Do **not** enable evaluation in the retail Gameplay edition. The benchmark definition's
`edition:"gameplay"` describes career semantics, not permission to open a retail eval endpoint.
The bundled adapter now requires capability `build_edition:"training"|"testing"` AND
`career_semantics:"gameplay"`. Each normalized row records the actual `build_edition` separately.

Minimal extra EnvConfig field requested: `bool gameplayCareer` parsed from `gameplay_career`,
default false. Honour it only when `EditionRules.AllowEvaluation` is true and the request is a
validated nonlearning benchmark career. It gives shift 1 no Karen body/senses/actions/contact
while keeping the store/Director/Ledger alive to record habits. Do not implement it by disabling
the entire Karen bootstrap. At each career's shift transition honour the request's exact layout
(the existing `layout`, `heldout_layout`, `training_layouts:false`, `start_shift` fields suffice
if reapplied per shift). The benchmark handler constructs the actual Persona/Employee mind,
retains BotMemory for all four shifts, and applies `ledger` retained/wiped to Karen only. No
new EnvConfig persona field is needed if the handler does that directly. `purpose` is evaluate
only; training/tuning requests must never take this held-out route.

`benchmark_career` request additionally carries `career_semantics:"gameplay"`; the rest of the
transport contract above is unchanged. Unsupported server/model/semantics fails explicitly.

## Final Python adapter correction for parent

`executed.traits` compares identical key sets with finite numeric values and **absolute error
<= 1e-6 only for traits**, accepting Unity float32 roundoff from the seeded Python doubles.
All other execution fields remain exact comparisons. Return only the requested trait keys
there (scripted profiles request `{}`); optional top-level `actual_persona` can retain all 14
actual traits and is archived with the full raw response. No wire field has been renamed.

Parent's current hook omits `metric_samples`, so panic RMSE and the derived adaptation RMSE
delta remain unavailable. Emitting a default RMSE of zero does not establish an observation.
The adapter accepts complete `uses_*` counters only with `trick_counts_complete:true` (or an
explicit `trick_counts` mapping). `pacing:false` enables survival evidence, never the `-1`
catch-time sentinel. A runtime selected model hash is still unknown: `--model-file` therefore
fails safely until capabilities can attest it. The compiled commit must match requested source
provenance; the parent sources it from clean `build-provenance.json`, never request metadata.

The Python runner now rejects successful exits with incomplete schedules while preserving raw
rows for explicit offline scoring. Safety gating cannot pass when wiped-condition fairness
measurements are missing. `stuck` currently means EpisodeMetrics `timed_out`, an overtime-cap
proxy; no stronger stuck/pathfinding claim is made.

## Remaining actual integration limits

- No Unity, deployment, training or git commit was performed. The parent's new C# sources
  have not been exercised in a compiled game here. Real suites require an evaluation build,
  clean matching compiled provenance and the actual trained Employee mind: full frozen halves
  include trained-range/careful-corner, so missing trained players fail preflight even for a
  planner arm. Basic/Vital additionally require their real trained brains.
- Prediction probability/calibration evidence, belief timings, consented
  held-out human reference data and exact neural decision sidecars are not supplied by current
  summary metrics. These scores/panels remain unknown; recurrent attribution is unsupported.
  Bot adaptation beyond retained/wiped Karen RMSE needs separate evidence/score definition.
- Existing record/fit/train commands are not automatically instrumented or gated. The wrapper
  and APIs are usable now; callers must opt in. Register import supports offline Windows
  records, but no Windows execution was tested. Hidden-once protection is a local claims file,
  not a secure way to conceal public seeds or prevent deliberate relabelling.
- A verified claude.ai write/auth integration is unavailable. The working private local HTML
  and authenticated loopback fallback are delivered; phone-accessible remote hosting is not.
  The launchd plist is generated only, not installed. No week of real collection or scheduler
  uptime is claimed; synthetic retention tests do not establish elapsed-day operation.
- GitHub is opt-in via existing `gh`; live GitHub collection was not requested/run here.
  YouTube, Buffer, Steam wishlists, cloud playtests and private asset collectors remain explicitly
  unavailable without configured sources/accounts. No credentials or real status numbers
  were placed in repository files.

The final parent integration adds the C# benchmark career/server handler and real RMSE sample
counts. The server verifies arm, seed, ledger path, physical presence and exact layout; it rejects
trainer/demo launches and keeps the same loaded model selection across a career. These C# paths
