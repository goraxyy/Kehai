# 0.5.0 AI integration — reviewed source handoff

14 November 2026. Changes are direct in the shared `0.5.0-build` worktree, no commits.
The current build instruction and final choices supersede the old implementation hold.

## Parent contracts

- `GeneratedEmployeeMind.Trained => net.Card.Trained` is public/read-only. It reports the
  actual loaded card, including false for handmade fixtures. Benchmark eligibility and
  preflight remain parent-owned; this property does not silently promote a fallback.
- `KarenStats.PacingSamples => pacingSamples` is public/read-only. Use it for
  `metric_samples.panic_setpoint_rmse`; zero samples means unavailable. Existing RMSE
  arithmetic is unchanged.
- Presence goes through the global `Edition.ShouldKarenAppear(int shift)`, including the
  parent's `CareerRuntime.GameplaySimulation` flag. No direct EvalConfig dependency.
- Parent's regular `SimulatedPlayers` call to `Memory.ObserveFair(obs, now)` is present;
  EmployeeObservation also observes at decision time. Calls do not double-count continuous
  encounters/chores. This review did not edit SimulatedPlayers, EnvWorld, KehaiEnv, EnvServer,
  League, EvalSplits, layouts, StoreMap, or another worker's world/trick implementations.
- BeliefTrace writes `<requested-root>/<layout>/map.json` and traces. Central refit manifests
  point at these leaf folders. Parent owns other consumers of trace paths.

## What was checked and fixed

- Gameplay upcoming shift 1 suppresses the body in initial Start, before clock-in, as well as
  at BeginShift. It is not temporarily reactivated for an absent shift. Director/Ledger
  continue at the normal Director cadence; policy, dash, sight and environmental tricks do not.
  Shift 2 restores the body and configured sensing. Changing rung or rebuilding the map cannot
  re-enable absent Karen's sense subscriptions. Native movement calls guard inactive agents.
- PlayerSenses checks presence/body activation before the cached bot-sense path. Parent owns
  EnvWorld's corresponding guard. KarenBootstrap gates ReviewScreen by ShowUI, diagnostics by
  AllowDebugTools, and replay/clip recorders by RecordReplays; Training retains shift and
  learning records. No Training UI/Unity runtime claim is made from compilation alone.
- Ledger regions, routes and placement memory are layout-scoped; legacy spatial habits belong
  to `today`. Other layouts fade while unvisited. Old unsorted `door_N` identities cannot be
  safely mapped to sorted doors: those rows leave active memory, but the exact original save
  is preserved first as `<ledger>.pre-0.5.0.json` (unique suffix if an older backup differs).
  Safe tile and nonspatial habits survive. Future-version/unreadable saves are not overwritten.
- Escape truth stays Director/recorder-owned and is copied into staged records. Only EndShift
  commits local counts, once; wrong shift/layout rows are ignored. Counts fade and blend with
  the explicit prior. No local neural fitting. Zero-evidence habit updates preserve baseline
  values exactly; the current true route is never an input to the hunt.
- The older replay failures in `/tmp/kehai-050-pytests.log` are resolved: untimed truth samples
  keep ordinary scores/parity without invented post-loss labels. Central top-three scoring now
  ranks adjacent next regions rather than unrelated distant destinations. Real fits remain
  deferred; the dry-run tests use synthetic traces and do not demonstrate a behavioral gain.
- BrainNet/export support one-layer ML-Agents LSTM with caller-owned hidden/cell state.
  Cached weights share no bot memory; each GeneratedEmployeeMind clears its memory at shift
  boundaries. Employee observation v2 requires a new employee export. ModelPack validates the
  employee observation version and reads recurrence; Karen pack recurrence remains unsupported.
- New repair response timers cover `flash_sale`, `screen_loop`, `room_lights`, `freezer_alarm`,
  and `complaint`, using the existing world events and TaskManager.Changed for complaint start.
  Multiple fixtures have separate timers. `Answered` feeds existing Ledger counterplay,
  stats and ShiftRecorder answer rows; the central `fit_start` already reads those rows.
  Generic policy-decision learning records remain separate. Automatic sale termination at
  closing/end, disabled fixtures, complaint timeout and shift reset do not become repairs.
  Player-originated light-off actions do not start Karen response timers. Optional escape
  diagnostic write failures no longer interrupt Ledger settlement/shift cleanup.
