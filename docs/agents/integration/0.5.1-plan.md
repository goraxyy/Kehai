## Implementation boundaries

- Keep one 0.5.1 PR; implementation is blocked on the owner's later go, not on this plan's merge.
- Encode repeatable placement/lighting changes in C# builder/runtime code. Scene, prefab,
  material, generated helper binary, Packages and ProjectSettings files stay out of git.
- Scene application must be repeatable without duplicate labels/components. Record local
  application separately from source delivery, and regenerate scene/navigation maps using
  their tools after actual changes; never hand-edit generated maps.
- Preserve fair sensing: observed entry creates a last-seen search target, not continuing
  access to the player's actual hidden position. Catch requires physical reach, not a kill
  through a closed door. Test leaving the hiding place after sight is lost.
- Apply one power rule to every automatic-door request, including Karen and phantom chimes.
  Reconcile overlapping global blackout and room-light effects; restoration must not leave
  doors or lights disabled, nor cancel an unrelated effect. Check navigation through stopped
  panels and access to the power repair so blackout cannot trap a shift permanently.
- Inspect ambient/sky contribution, baked or probe lighting, emission, exposure, fog and local
  lights together. Do not substitute a screen overlay for actual lighting changes. Check
  perception's darkness input against the rendered state rather than silently retuning Karen.
- Two-way manual opening must respect panel collisions. Reversal changes target from the
  current angle with no snapping; locks/physical blocks still prevent invalid movement.
- Helper work includes compile/setup instructions, lookup and packaging for supported targets,
  with consent and process cleanup preserved. No camera recording or activation in this plan.
